Design Foundation

The tokens, typography, components and patterns behind this site — self-documenting: the navbar above and footer below on this very page are the live components, not screenshots.

Architecture

Everything here is Scratchpad CSS, a self-contained framework under _sass/scratchpad/ — no external UI library. One entry point imports every layer in a fixed order (it's @import, one shared global scope, so order matters):

  1. abstracts — build-time SCSS only: breakpoints, z-index scale, the light/dark colour maps, mixins. Nothing here reaches the browser directly.
  2. tokens — turns the abstracts into runtime --sp-* custom properties on :root, plus the [data-color-scheme] dark overrides. This is the single source of truth every other layer reads from.
  3. base — reset, element typography, background/motion patterns (grid, dots, scroll-reveal).
  4. layout — containers, navbar, hero, content shell, footer: the structural chrome shared by every page.
  5. components — buttons, cards, collection cards, post/article, search, home, resume, sitemap: the reusable UI pieces.
  6. utilities — spacing / text / flex helpers, imported last so their !important rules win.

Every class that reaches HTML is prefixed sp- (sp-card, sp-btn, sp-pcard--video…) and reads var(--sp-*) tokens — nothing is hard-coded, so the whole site re-themes from one place.

Color tokens

Sourced from one map in abstracts/_config.scss ($theme-light / $theme-dark) and emitted as --sp-color-*. This site's palette is deliberately monochrome — accent and contrast are pure black in light mode, pure white in dark mode. Typography & font pairing

Two families, one job each — loaded via site.fonts in _config.yml.

Geist — UI & body

Every heading, paragraph, label and button. Variable weight (100–900), system-stack fallback (-apple-system, Segoe UI, Roboto, Inter…) so text never flashes unstyled.

Caveat — the handwritten accent

Used sparingly, on purpose: the hero quote, the "that's me!" tag, the signature. It's a voice, not a body font — never used for anything you have to read at length.

Navbar

You're looking at it — the header on this page is the component, driven entirely by site.header in _config.yml.

  • island | full — island starts as a normal bar, then detaches into a floating rounded pill once scrolled (.is-scrolled). It keeps the site width throughout; only height, padding, radius and surface change, so its edges stay locked to the content below.
  • Progress ring — an SVG path traced around the pill's own rounded outline, left → bottom → right → top, revealed with stroke-dashoffset as you scroll (navbar.js). Path length, not angle, so it moves at one constant rate around straights and corners alike.
  • Brand mark — a circular "SS" initials avatar beside the name, identical in the top bar and the scrolled pill. Initials rather than a logo image, derived from site.author.
  • Dropdown / megamenu — item.children for a simple list, a child with its own children for a two-level flyout, megamenu: true + groups for the large grouped panel.

Dark mode

An inline no-flash script in head.html writes data-color-scheme (light / dark / system) onto <html> before first paint. The navbar's sun/moon toggle flips it and persists the choice to localStorage (sp-color-scheme). Every token above is redefined under [data-color-scheme="dark"] in tokens/_dark-mode.scss — components never branch on theme themselves, they just read the same var(--sp-color-*).

Motion & background accents

Kept subtle and always prefers-reduced-motion-aware.

  • Dot / line grid — .sp-bg-dots / .sp-bg-grid, a radial or linear pattern masked so it fades into the page rather than tiling edge-to-edge.
  • Hero glow — a soft, slowly drifting accent-colour circle behind the hero grid, on a 16s float loop.
  • Ambient hero video — on the homepage, a muted/looped YouTube embed sits behind the copy, masked with a closest-side circle (guaranteed to reach full transparency before any edge) and mix-blend-mode: screen so dark frames melt into the page instead of reading as a grey box — desktop only, skipped under reduced motion.
  • Hero choreography — a GSAP timeline (hero.js, loaded only on pages with a hero_title): the photo settles in, title words rise from behind per-word masks, the rest of the copy staggers up. Then a slow idle float, a pointer-following drift on fine pointers, and a scroll lift on the copy. No CSS sets a hidden start state, so without GSAP the hero just renders.
  • Scroll reveal — .sp-reveal elements fade/rise in via an IntersectionObserver (custom.js); content stays fully visible if JS never runs.
